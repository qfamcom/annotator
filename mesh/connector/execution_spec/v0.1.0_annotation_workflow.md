# Connector Execution Spec - v0.1.0 Annotation Workflow

## Scope
- In scope:
  - Implement adapters and workflows needed for render/export conversions.
  - Validate connector contracts with app and infra expectations.
- Out of scope:
  - User-facing workflow implementation.

## Preconditions
- Required approved plan spec links:
  - `connector/plan_spec/v0.1.0_annotation_workflow.md`
  - `app/plan_spec/v0.1.0_annotation_workflow.md`
  - `infra/plan_spec/v0.1.0_annotation_workflow.md`
- Required contract versions:
  - `mesh_bus/integration_state.json` version `0.1.0` status `draft`
  - `mesh_bus/api_contract.json` version `0.1.0` status `draft`

## Step Sequence
1. Implement parser/renderer adapter interface and baseline PDF page extraction.
2. Implement annotation overlay adapter with version-aware input contract.
3. Implement JPG conversion path producing one image per page.
4. Implement ZIP packaging adapter with deterministic page order.
5. Wire adapter errors into retryable/non-retryable categories.
6. Execute contract validation checks for adapter schemas.
7. Execute end-to-end export verification scenarios with app flow.

## Acceptance Criteria
- Connector interfaces produce deterministic page order and traceable page IDs.
- JPG export output is ZIP package containing one JPG per page.
- Adapter failures are observable and categorized for retry behavior.
- Contract checks pass for integrated app/connector flows.

## Validation Plan
- Tests:
  - Adapter contract tests.
  - Integration tests for conversion + packaging path.
  - Golden-file regression tests for representative documents.
- Manual checks:
  - Visual verification of annotated overlay fidelity in PDF and JPG outputs.

## Rollback / Recovery
- Rollback trigger:
  - Conversion correctness failures or severe export regressions.
- Rollback method:
  - Revert connector adapters to previous stable version and disable affected export format path.
