# App Execution Spec - v0.1.0 Annotation Workflow

## Scope
- In scope:
  - Implement upload, annotation persistence, export request, and export status flows.
  - Enforce file/page limits and output format rules.
- Out of scope:
  - Collaboration, OCR, or advanced annotation intelligence.

## Preconditions
- Required approved plan spec links:
  - `app/plan_spec/v0.1.0_annotation_workflow.md`
  - `infra/plan_spec/v0.1.0_annotation_workflow.md`
  - `connector/plan_spec/v0.1.0_annotation_workflow.md`
- Required contract versions:
  - `mesh_bus/api_contract.json` version `0.1.0` status `draft`
  - `mesh_bus/integration_state.json` version `0.1.0` status `draft`

## Step Sequence
1. Implement document intake flow and metadata validation.
2. Implement page-level annotation CRUD with durable save semantics.
3. Implement export request API and asynchronous status polling.
4. Integrate PDF export and JPG ZIP export output handling.
5. Enforce v1 limits (50 MB file size, 100-page max).
6. Add metric instrumentation for persistence completeness and export outcomes.
7. Execute regression scenarios for mixed page annotations and both export formats.

## Acceptance Criteria
- Upload rejects invalid files and accepts in-scope PDFs.
- Annotation updates persist and remain recoverable across sessions.
- Exported PDF and JPG ZIP include all annotated pages.
- Export success tracking supports threshold reporting against >= 99.0% target.

## Validation Plan
- Tests:
  - Unit tests for annotation persistence logic and state transitions.
  - Integration tests for upload->annotate->export path.
  - Contract tests against API schemas.
- Manual checks:
  - Multi-page sample with sparse annotations.
  - Full-document annotation sample at upper page/file bounds.

## Rollback / Recovery
- Rollback trigger:
  - Data integrity regression or export failure spike.
- Rollback method:
  - Revert to last stable app release and disable new export initiation while preserving read access.
