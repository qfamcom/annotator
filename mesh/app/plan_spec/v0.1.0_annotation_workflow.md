# App Plan Spec - v0.1.0 Annotation Workflow

## Objective
Define v1 application behavior for PDF upload, page-level annotation, and export output with complete annotation persistence.

## In Scope
- Upload PDF documents (up to 50 MB and 100 pages).
- Present pages for annotation/marking.
- Persist annotation state for all annotated pages.
- Export annotated output as:
  - annotated PDF
  - JPG package (ZIP with one JPG per page)
- Track asynchronous export status.

## Out of Scope
- OCR/semantic extraction features.
- Collaboration and multi-editor concurrency features.
- Non-PDF input formats for v1.
- Multi-repository governance workflows.

## Functional Requirements
- Upload:
  - Accept valid PDF and reject unsupported inputs.
  - Record document metadata and page count.
- Annotation:
  - Support creating/updating/removing marks at page level.
  - Persist annotations independent of rendering surface type.
- Save behavior:
  - Ensure annotated page state is durable and recoverable.
- Export:
  - Start export jobs for selected output format.
  - Include all annotated pages in resulting artifact.
  - Return export status and artifact retrieval info on completion.

## Non-Functional Requirements
- Annotation persistence completeness = 100% for annotated pages.
- Export success rate >= 99.0%.
- Deterministic behavior for repeated export requests on same annotation version.

## Data/State Expectations
- Document state: uploaded, parsed, ready, failed.
- Annotation state: draft, saved.
- Export state: queued, processing, complete, failed.

## QA and Release Metrics
- Dynamic fixed-random sampling with 10% default for annotation QA pass checks.
- Measurable export success and turnaround metrics.

## Risks and Mitigations
- Risk: page-level annotation mismatch during conversion.
- Mitigation: canonical coordinate model and versioned annotation snapshots.

- Risk: export drift between PDF and JPG outputs.
- Mitigation: shared render pipeline and cross-format regression checks.
